# Текущий статус: метрическая модель и проверка полезности

76 автоматических тестов пройдены. Новый каталог содержит согласованные XYZ для 28 объектов; 9 длин равны табличным, суммарно 21,91 км. Пространственные допущения открыто указаны. Гидравлика и алгоритм ранжирования по новым исходам не подгонялись.

Новый аудит содержит 6048 случаев и 7 стратегий; план сохранён до расчёта. Внутри сетки: 615 улучшений против текущего разброса, 2841 равенство. Приоритет метана лучше в среднем; вне сетки достоверность низкая. Полные ограничения: SENSOR_UTILITY.md.

На работающей платформе проверены запуск, 28 Things, 12 сценариев, replay и 4 панели истории. Парный ремонт из одинакового опыта для трёх стратегий проверяет реальные задержки и фактический выигрыш: live-sensor-comparison.json. В нём прогнозный выбор и текущий разброс равны, приоритет метана не даёт сужения к тому же целевому времени. Отказ MQTT проверяется отдельно: устаревший снимок даёт 503, после восстановления читается Ditto. Новая чистая установка из поставляемого ZIP имеет отдельный отчёт clean-install-report.json рядом с архивом.

Среда проверки — Windows + Docker Desktop Linux, с кэшем базовых образов. Это не судейская Ubuntu и не полевые испытания. Официальная публикация не выполнялась.

## История предыдущих проверок

### Ранний статус v3

Локальная связанная модель и API реализованы. Пройдены 70 тестов: 50 прежних регрессий и 20 новых проверок сети, API и платформенных контрактов. Воздух, перенос, наблюдение, сценарии и воспроизведение проверены. Отчёт содержит 576 случаев и отрицательные результаты.

Живая интеграция OpenEgiz подтверждена 25 октября 2026. `platform-check.json` фиксирует прямое чтение 28 Things с совпадающими состояниями/ревизией, прохождение команд, закрытие связи, ремонт измерения и отмену сценариев. Отдельно MQTT-брокер был кратко остановлен: устаревший снимок вызвал HTTP 503, локальная подмена отсутствовала, после запуска брокера данные Ditto восстановились. Интерфейс проверен с источником Ditto; история графика тоже проходит через платформу.

Фактическая среда: Windows + Docker Desktop, Linux Engine 28.5.1. Это не проверка на чистой судейской Ubuntu 24.04 с Engine 29.1.3. Первый запуск скачивает образы и npm-зависимости. Исходник Extended API загружается по зафиксированному коммиту с SHA256; кэш и секреты исключены из поставки.

Docker был восстановлен без сброса: временные каталоги IPC сохранены под именами `run.ventobserve-preserved-20261025-2203`, `run.ventobserve-preserved-20261025-2206` и `docker-secrets-engine.ventobserve-preserved-20261025-2206` рядом с прежними каталогами в LocalAppData. Образы, тома, настройки и пользовательские данные не удалялись. В проекте исправлены Windows Bake build context и окончания строк shell-скриптов.

Официальный репозиторий команды и состав команды не предоставлены. Публикация не выполнялась. Дедлайн на официальной странице проверен 25 октября 2026: 23:59 по Астане (UTC+5). Не обещается конкурсная оценка или промышленная пригодность.


## Дополнение: изометрия и проверка истории

Обновлён интерфейс: изометрический разрез, переключение схемы, карточки объектов, быстрые сценарии, возраст снимка, подтверждения команд, пояснение паузы. Воспроизведение JSON поддержано в режиме платформы с сохранением чтения UI исключительно из Ditto. 72 автоматических теста прошли.

Обнаружена остановка поступления свежих рядов в InfluxDB при работавшей передаче снимков Ditto. Универсальное рекурсивное разворачивание payload заменено ограниченным извлечением скалярных метрик. Проверка четырёх панелей сохранена в dashboard-check.json. Новые проверки всех сценариев и replay — ui-platform-check.json. Геометрия сцены условная, параметры физической модели не изменены.


Итоговое исправление истории: Telegraf опрашивает только четыре числовых feature в Ditto по HTTP каждые 5 с. Временная метка берётся из sample.wallTime, поэтому старое значение не становится новой точкой при обрыве. MQTT остаётся обязательным входным транспортом двойников. Это также устраняет зависание mqtt_consumer после неудачного повторного подключения (наблюдалось с Telegraf 1.37). Ранее описанное извлечение из событий заменено этим окончательным вариантом. Во время недоступности платформы возможны пропуски истории.
