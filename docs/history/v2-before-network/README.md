# VentObserve

Цифровой двойник синтетического вентиляционного участка. Показывает воздушные потоки, динамику метана и неопределённость при потере датчиков. Рейтинг сравнивает, какое измерение восстановить первым. Это исследовательский стенд; промышленные характеристики и эффект не подтверждены.

## Локальная демонстрация

Требуется Python 3.11 или новее. Внешние библиотеки не нужны.

```text
python -m app.server
```

Открыть http://127.0.0.1:8765 . Остановка: Ctrl+C. Локальная демонстрация не выполняет обязательную платформенную интеграцию конкурса. Вкладки управляют одним экспериментом; состояние хранится в памяти.

## Что изменилось в локальной версии

Пять этапов: измеримая задача инженера; падающая характеристика вентилятора и отдельный опубликованный пример Gucheng; последовательные интервалы с шумом/задержками/зависанием; сравнение стратегий на 1536 случаях; контрольные точки, стоимости, объяснения и воспроизведение JSON с seed.

Интервалы условны относительно модели и границ ошибок. Выход за границы без измерений может остаться незамеченным. В проверенной матрице рейтинг совпал с простым правилом «ширина / стоимость»; преимущества сложности не установлено.

Проверки: `python -m unittest discover -s tests -q` (50 тестов), `python -m app.reference`, `python -m app.evaluation`. Полный отчёт: `docs/evaluation.json`, постановка: `docs/OPERATOR_TASK.md`, модель: `docs/MODEL.md`, план и итог каждого этапа: `docs/IMPROVEMENT_LOG.md`, сценарий показа: `docs/DEMO.md`.

## Статус интеграции

Платформенная интеграция исключена из этих пяти этапов по запросу пользователя. Существующие `integration/` и `openegiz/` сохранены как прежняя подготовка; текущая совместимость с живыми MQTT/Ditto/Grafana не проверена. Ранее запуск Docker Desktop блокировался ошибкой IPC-сокета dockerInference. Официальный репозиторий команды пока не выдан. Локальный стенд не закрывает требования платформенного запуска конкурса.

## Ранее подготовленная платформенная архитектура (не проверена для этой версии)

Модель → MQTT (Ditto protocol) → 11 Things Eclipse Ditto → API интерфейса. Типы, физические связи, единицы и измеряемые объекты заданы в `app/platform.py`. Телеметрия содержит ID эксперимента, ревизию и время. Корневой снимок публикуется последним; MQTT не обеспечивает атомарность записи нескольких Things, поэтому метки позволяют выявлять смешанные ревизии.

В платформенном режиме `/api/state` читает корневой снимок из Ditto. При ошибке или возрасте более 15 секунд API возвращает 503; локальной подмены нет. Команды поступают симулятору по HTTP и становятся видны после прохождения платформы. JSON/CSV являются явно помеченным локальным аудитом симуляции. Grafana dashboard подготовлен, но с живой платформой не проверен.
